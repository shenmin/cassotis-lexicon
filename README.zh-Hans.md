本仓库用于构建和发布 Cassotis IME（言泉输入法）的简体、繁体基础词库及候选排序统计表。言泉输入法安装包已内置词库与统计表，普通用户直接安装输入法即可，无需单独下载。

## 仓库职责
- 基于开放词源与项目维护的补充词表，构建简体与繁体基础词库（包含构建脚本、来源清单及生成产物）。
- 随版本同步发布供 Cassotis IME 导入的排序与补全统计表，包括路径先验、词间转移、字符 n-gram、补全索引、通用文本词频、日常对话词频及短词首选表。
- 支持从公开外部词源可复现地重建完整词库（`external_broad`）。
- 维护与生成产物严格对应的来源署名及许可证文件。

繁体词库的多字词统一采用台湾用字（為、裡、著、群、吃）；单字词库保留异体字，方便按需单独输入。字形对照见 [台湾用字表](manifests/traditional_taiwan_forms.tsv)。

专业词汇仅以低权重补充缺漏词条，不抬高已有词条和单字的权重。输入完整拼音可选取冷门专业词，但这类词默认不参与短前缀补全与 Tab 预测；“有限责任公司”“文件系统”等经过复核的通用表达仍保留正常补全资格。收录范围与来源见 [专业词准入记录](manifests/vertical/thuocl_specialist_admissions.tsv)，保留补全资格的通用表达见 [独立清单](manifests/specialist_common_terms.tsv)。

词库还收录了 7,747 句古诗词，选自中小学课本、《唐诗三百首》《千家诗》和《宋词三百首》（`manifests/curated_daily_supplement_phrases.tsv`）。输入前两个音节起，一键补全区即可提示整句；打完整句拼音时排在候选首位，续写索引还会继续提示下一句（`manifests/classical_poetry_next_lines.tsv`）。

## 供 Cassotis IME 排序的数据

除基础词表外，本仓库还发布供 Cassotis IME 导入本地 SQLite 词库数据库的统计表。这些统计表仅用于排序与补全，并非可直接输入的词条，因此不计入上方的词库快照。表中仅记录频次、词对关系与字符 n-gram，不包含语料原句，且统计来源已排除输入法的基准测试集。输入法自身的字符级语言模型、决策策略与结构排序器由 IME 主仓库负责训练和发布，详见 [模型与排序](https://github.com/shenmin/cassotis-ime/blob/master/README.zh-Hans.md#模型与排序)。

下表中的版本区间表示对应版本的发布产物保持一致；各项记录数均不含文件表头。

短词首选表（`data/generated/dict_short_promotion_{sc,tc}.txt`）针对二至四音节查询，预先记录仅凭词库排序时应当排到默认首词之前的精确匹配词条。该表由 Cassotis IME 的专用离线工具根据构建好的词库生成（见 IME 仓库的 `out/rebuild_short_promotion.ps1`），用以替代早期的运行时短词残差模型（该模型现仅保留在此离线生成工具中）。每条记录均附带决策时的候选词列表及权重，仅在词条与权重未变时生效；旧版词库遗留的不匹配记录会自动跳过，不会引发错误。

通用词频表（`data/generated/dict_word_frequency_{sc,tc}.txt`）记录二字及以上词条在通用中文语料中独立成词的出现频次，按 `100 * log10(1 + 次数)` 折算分值；繁体词条沿用对应简体形式的频次。原始计数（`manifests/general_word_counts.tsv`，由 `scripts/count_general_word_frequency.py` 生成）统计自 Cassotis IME 字符级语言模型的通用语料，采用最少词数切分，因此包含在长词内部的短词不重复计入。后续新增词条仅统计其独立成词频次，不影响既有词条计数。无上文时，Cassotis IME 会参考该表在同音词之间做取舍。

会话词频表（`data/generated/dict_conversation_frequency_{sc,tc}.txt`）采用相同的切分与折算方式，统计日常对话语料 LCCC-large（Wang 等，“A Large-Scale Chinese Short-Text Conversation Dataset”，NLPCC 2020；MIT 许可证）中的词频（原始计数见 `manifests/conversation_word_counts.tsv`，仅保留频次）。无上文时，若词库默认首词在日常对话中远比竞争词常见，而通用语料仅微弱偏向后者，Cassotis IME 会依据该表保留默认首词。由于 LCCC 语料经过敏感词过滤，未出现在表中的词仅视为缺少对话统计，不作为降权依据。

输入法构建运行时词库时会强制校验这三张表，缺失任意一张都会直接报错中止，避免在未察觉的情况下导致短词排序质量下降。

### 五笔 86 码表

`data/generated/wubi86_table.txt` 是 Cassotis IME“五笔混输”方案（五笔 86 编码与全拼混合输入）的码表，由 `scripts/build_wubi86_table.py` 根据孙海峰的五笔 86 单字与词组码表（BSD 3-Clause，见[来源说明](attribution/ATTRIBUTION.md)）生成；原始文件按固定提交下载并校验 SHA-256。码表共 129,839 条、107,199 个编码，包括单字的全码与各级简码，以及 65,166 个词组，均保持原表顺序。原表留空的编码补入单字的五笔 86 容错码，以及按五笔 86 组词规则编码的 38,567 个常用词库词条；补入的条目只占空码，不改变任何原有条目的位置。码表与拼音词库相互独立：拼音词库的构建步骤不读取它，上文的词条数不包含它，Cassotis IME 只在五笔混输方案下加载。

## 导入后的优化与过滤（外部来源）
- 对不同格式词源导入的词条做规范化与去重处理。
- 综合基础词频、文档频率（DF）及页面浏览热度计算权重，并做均衡缩放。
- 从已有充分依据的长口语短语中提取常用短前缀，使常见句式转折与衔接表达更容易靠前出现。
- 压低缺乏多源佐证的专有名词、疑似人名及长尾噪声权重，防止冷门专名挤占常用词。
- 执行面向输入法场景的合法性过滤（如字形可显示性与字符集范围校验），确保生成的词条适配主流 Windows 应用环境。
- 结合规则修正与回归测试样本校验，确保跨版本排序行为稳定。

## 覆盖重点
- 优先保障日常表达与对话式输入体验，而非单纯追逐网络热词。
- 利用开放词源补齐常用短表达、句式转折、语气词与口语连接词。
- 对开放词源遗漏的高价值日常表达，通过精简的项目维护白名单定向补充。
- 将专有名词与网页热度控制在次级权重，避免干扰核心日常输入路径。

## 分层策略
- `manifests/curated_daily_phrases.tsv`：专门收录享有日常输入优先加权的常用口语与聊天短语。
- `manifests/curated_daily_supplement_phrases.tsv`：收录低频日常补充词条，保证完整拼音输入时可选，但不享有日常聊天短语的高优先级权重。
- 上述补充词表可选配第五列模式（在常规排序与路径统计完成后生效）：`exact_zero` 生成零权重的精确匹配词条；`exact_rank` 将清单中的非负分值直接作为固定的精确候选权重；`no_contains` 使词条不写入运行时的子串流行度索引；`exact_rank_no_contains` 同时启用 `exact_rank` 与 `no_contains`；`exact_rank_exact_only` 在此基础上进一步禁用前缀补全（仅在输完完整拼音时出现）。
- `manifests/vertical_layers.public.json` 声明各独立领域词层的配置与词源，`manifests/vertical/*.tsv` 存放项目维护的各领域词表。所有领域词层均独立于日常聊天短语的优先加权路径之外，避免专业词汇与专名干扰日常输入：
  - 小说实体层（`fiction_entities`）：收录小说人物、作品名与设定词汇，与日常短语及一般专名隔离。
  - 一般专名层（`proper_nouns`）：收录头衔、机构、品牌、平台、产品等非人名现实专有名词。
  - 人名层（`people_names`）：收录公众人物与历史人物姓名（与小说人物及非人名专名隔离）；其中 Wikidata 补充人名采用保守权重，保证输入完整姓名时可选，同时不挤占常用词。
  - 地名层（`place_names`）：以保守权重收录国内外地名、国家地区、世界主要城市、景点与地标；Wikidata 补充地名的权重低于项目维护词条，使冷门行政区和地标在完整输入时可选，但不会压过常用词。
  - 成语典故层（`idioms_allusions`）：包含过滤后的 `THUOCL_chengyu` 子集与项目维护的成语典故，采用保守权重，支持完整成语输入且不挤占日常短语。
  - 计算机层（`computing`）：包含过滤后的 `THUOCL_IT` 子集与项目维护的计算机术语。
  - 政务民生层（`civic`）：收录税务、房产、户籍及其他公共服务相关术语。
  - 建筑术语层（`architecture_terms`）与建筑实体层（`architecture_entities`）：前者整合项目维护术语、Getty AAT 建筑术语及 Wikidata 建筑构件/风格词条；后者包含项目维护建筑实体及保守权重导入的 Wikidata 建筑地标。
  - 游戏层（`gaming`）：整合项目维护游戏用语、Wikidata 游戏实体，以及过滤后的中文维基百科与维基词典（`zhwiki`/`zhwiktionary`）游戏词条。
  - 游戏开发层（`game_dev`）：整合项目维护开发术语、过滤后的 Godot 中文文档标题、Wikidata 游戏引擎名称，以及过滤后的 `zhwiki`/`zhwiktionary` 相关词条。
  - 医学层（`medicine`）：整合项目维护医学术语、MeSH 主题词目录、关联 MeSH 的 Wikidata 医学实体，以及过滤后的 `THUOCL_medical` 子集。

## 构建与校验

```powershell
# 全量重建（external_broad + unihan_single + regression checks）
.\rebuild_all.ps1

# 可选：生成待人工审核的人名候选；不会自动导入正式词库
.\scripts\build_people_names_candidates.ps1

# 直接构建单个 profile
.\scripts\build_external_seed.ps1 -Profile external_broad
```

仅修改多字词表时，全量重建会保持现有的 Unihan 单字权重不变；仅在需要重新校准单字排序时，才需使用 `-RefreshUnihanSingleCharWeights`。

同一读音下的单字按现代文本中的实际使用频率排序（`scripts/build_single_char_frequency.py`，2026-10-27）。早期单字顺序依赖 Unihan 频次、上世纪八十年代《现代汉语频率词典》及学段字表分级，导致部分读音下生僻字排到了常用字前面。现行脚本将该读音原有的权重集合按现代字频重新分配给同音单字，使用最频繁的字获得最高权重。字频统计综合了字符级语言模型通用语料中的总频次与独立单字（多字词之外）频次（`manifests/general_char_counts.tsv`，由 `scripts/count_general_char_frequency.py` 生成），以及聊天消息中单字独立输入的频次（私有统计，不公开）。每个字仅在其主读音下调整位次，同时严格保留人工审核的先后约束与回归测试样本。

在繁体词库中，对于“一简对多繁”的同源单字，由于通用字频基于简体统计，且语言模型处理繁体时同样先映射为简体字，两者均无法区分这些繁体字形的常用度。因此，这类单字在其主读音下按繁体文本的实际用字比例排序：先将通用语料逐句经 OpenCC 转为繁体并统计各字形占比（`manifests/traditional_char_shares.tsv`，由 `scripts/count_traditional_char_shares.py` 生成），再由 `scripts/order_traditional_shared_chars.py` 完成排序。台湾文本中未使用的异体字排在已出现字形之后；个别多音字因各读音权重接近，由人工指定参与重排的主读音。日常全量重建会保留上述单字权重；若使用了 `-RefreshUnihanSingleCharWeights`，需依次重新运行这两个单字排序脚本，最后再执行 `scripts/normalize_traditional_forms.py`。

当存在 `manifests/vertical_layers.public.json` 时，`external_broad` 与 `external_cedict` 构建流程会自动加载该配置。
