Cassotis IME（言泉輸入法）的詞庫建置與發布儲存庫：輸入法的簡體、繁體詞庫，以及它排序候選所用的統計表。每個言泉輸入法安裝檔都已包含這些內容，一般使用者無須從這裡另行下載。

## 儲存庫職責
- 從開放來源和專案維護的清單建置簡體、繁體基礎詞庫：建置指令碼、清單檔案與生成檔案。
- 每個版本同時發布 Cassotis IME 在詞庫之外匯入的統計表：路徑先驗、詞間轉移、字元 n-gram、補全索引、通用文本和日常對話的詞頻，以及短詞首選表。
- 支援從外部來源可重現地重建（`external_broad`）。
- 確保來源標示與授權檔案和生成產物保持一致。

繁體詞庫的多字詞統一採用臺灣用字（為、裡、著、群、吃）；單字保留異體，仍可刻意輸入。字形對照見 [臺灣用字表](manifests/traditional_taiwan_forms.tsv)。

專業詞彙以低權重補足缺漏，不調高既有詞彙及單字的權重。輸入完整拼音即可選取冷門專業詞，但預設不將它們用於短前綴及 Tab 預測；「有限責任公司」「綠豆湯」這類經過複核的通用表達仍可正常補全。收錄清單及來源請見[專業詞彙收錄紀錄](manifests/vertical/thuocl_specialist_admissions.tsv)，通用表達的補全資格另列於[獨立清單](manifests/specialist_common_terms.tsv)。

詞庫也收錄了 7,747 句古詩詞，取自中小學課本、《唐詩三百首》《千家詩》和《宋詞三百首》（`manifests/curated_daily_supplement_phrases.tsv`）。從打出開頭兩個音節起，一鍵補全區就可能提示整句；整句打完則排在候選首位，續寫索引接著提示下一句（`manifests/classical_poetry_next_lines.tsv`）。

## 供 Cassotis IME 排序的資料

除了詞庫，Cassotis Lexicon 也發布 Cassotis IME 匯入本機 SQLite 詞庫的統計表。它們並非可直接輸入的詞條，不計入上面的詞庫快照。這些表只保存計數、詞對和字元 n-gram，不保存語料中的句子；輸入法的基準測試案例不在它們的來源中。輸入法自己的模型（字元級語言模型、決策策略和結構排序器）由 IME 專案訓練及發布，請見其[模型與排序](https://github.com/shenmin/cassotis-ime/blob/master/README.zh-Hant.md#模型與排序)。

版本區間表示所列類別的發布產物維持一致。統計數量不包含檔案標頭。

查詢路徑先驗和詞級二元、三元轉移關係由 Lexicon 建置流程產生。Cassotis IME 用它們為長句的詞路徑評分，短詞和短語路徑也讀取同一拼音下的詞間轉移。具平滑退避機制的正向、反向字元級 n-gram 模型由 IME 訓練工具產生，再由本儲存庫統一進行版本管理與發布；輸入法仍會匯入它們，在語言模型之外作為統計特徵使用，例如補全排序和短詞首選表。

這些表的演變：
- **v1.1.0** 首次發布以語料訓練的統計語言模型資料：詞間轉移和正向字元 n-gram。
- **v1.10.0** 新增由語料證據支持、約束嚴格的 1+2 和 2+1 精確詞轉移，用於改善三音節短詞續接，同時避免引入缺乏依據的組合。
- **v1.11.0** 保留全部既有轉移權重，並從清理後的小說、聊天和大規模中文語料中獨立計數，擴充 1+2、2+1、2+2、2+3 和 3+2 精確詞轉移；新增項目還需通過來源支持、競爭路徑和已觀測同音詞的檢驗。
- **v1.12.0** 繼續擴充具生產力的詞轉移，並新增語料支持的相鄰單字 1+1 轉移關係。既有的二字精確詞會被排除；保留的 1+1 關係必須使用常用讀音，並獲得多個獨立來源的支持。
- **v1.13.0** 新增反向字元 n-gram 模型，用於雙向路徑評分。
- **v1.14.0** 更新查詢路徑先驗，以支援輸入法的精確詞錨定和短語續接路徑。
- **v2.3.0** 繁體各表改用臺灣用字，與同形詞合併後的記錄只保留一筆。
- **v2.5.0** 新增從字級語言模型的通用中文語料（FineWeb-Edu-Chinese、Ultra-FineWeb、中文維基百科；只用計數）中 1.2 億字統計的詞對，既有的轉移及其權重全部保留：簡體 289,955 → 904,767，繁體 257,124 → 833,707。只加入由兩個詞組成、且每個詞至少兩個字的路徑，另加六個單字詞對。含單字詞的新路徑會依通用文本的寫法把單字黏在詞上，降低了小說長句的首選；新增的單字詞對大多是通用文本的碎片，會在兩音節的鍵上排到首位；三個詞的路徑幾乎不起作用。
- **v2.6.0** 和 **v2.7.0** 隨讀音和繁體字形的修正更動了少量記錄，大多是繁體的。

短詞首選表（`data/generated/dict_short_promotion_{sc,tc}.txt`）記錄兩到四個音節的查詢中，只有詞庫可以依據時，哪個精確詞排到詞庫首詞之前。它由 Cassotis IME 從每個建置好的詞庫產生，產生程式是唯一還帶著被它取代的那個模型的程式（IME 儲存庫的 `out/rebuild_short_promotion.ps1`）。每筆記錄都寫明做決定時的候選詞和權重，只在它們不變時生效；舊詞庫留下的記錄會被略過，而不會出錯。

每個變體還有一份詞頻表（`data/generated/dict_word_frequency_{sc,tc}.txt`），記錄兩個字以上的每個詞在通用中文文本裡作為詞出現的次數，取 `100 * log10(1 + 次數)`；繁體詞取其簡體形式的次數。計數（`manifests/general_word_counts.tsv`，由 `scripts/count_general_word_frequency.py` 產生）來自 Cassotis IME 字級語言模型的通用語料，按把文本切成最少詞條的切分計數，所以長詞裡的短詞不計。後加的詞單獨計數（只算它獨立成詞的地方），其餘詞保留原有次數。Cassotis IME 在沒有前後文、同音詞之間取捨時使用這張表。

每個變體還有一份會話詞頻表（`data/generated/dict_conversation_frequency_{sc,tc}.txt`），做法相同，計數來自日常對話：LCCC-large 的語句（Wang 等，“A Large-Scale Chinese Short-Text Conversation Dataset”，NLPCC 2020；MIT 授權條款），按通用文本的方法計數（`manifests/conversation_word_counts.tsv`，只有計數）。沒有前後文時，Cassotis IME 用它保住詞典的首詞：日常對話裡這個詞常見得多，而通用文本只略偏向另一個詞。LCCC 過濾過敏感詞，表裡沒有的詞不算證據。

缺少這三張表中任何一張的詞庫，輸入法的詞庫建置都會報錯：沒有它們，短詞排序會悄悄變差。

v1.16.0 引入由語料推導的補全熱門度先驗與預先建立的 Top-K 前綴查詢索引，讓 IME 無須在執行階段列舉組合，就能區分熱門補全與冷門專業詞彙。熱門度先驗是獨立建置的快照，其數量不必與目前主詞庫一致。先驗紀錄數也不等於可提示的補全方案數；低頻專業詞彙是否用於短前綴或 Tab 預測，仍受獨立規則限制。

建置流程也會從強證據 exact 詞路徑離線產生獨立的轉移補全索引，每個輸入前綴最多保留六個經過複核的可靠方案。使用者補全仍優先；基礎詞庫與轉移補全方案則結合熱門度、前後文和語料證據比較。

## 匯入後的最佳化與篩選（外部來源）
- 統一不同來源的詞條格式，並移除重複項目。
- 綜合多個訊號（基礎頻率、DF/頻率側訊號、頁面熱度）計算權重，並做平衡縮放。
- 從已有充分依據的較長口語表達中衍生較短的日常/聊天前綴，讓常見句型轉折更容易優先出現。
- 降低訊號薄弱的專名、疑似人名和長尾雜訊權重，減少冷門專名排擠常用詞。
- 套用針對 IME 的有效性篩選（例如可顯示性與字元書寫系統限制），確保輸出適用於主流 Windows 用戶端。
- 透過規則修正與迴歸案例驗證維持排序行為穩定。

## 覆蓋重點
- 優先改善日常表達和對話式輸入，而不只追逐熱門詞。
- 藉助開放詞彙來源補回常見短表達、句型轉折、語氣詞和口語連接詞。
- 對開放來源仍然缺失但價值很高的日常表達，保留少量專案維護白名單。
- 將專名和網頁熱門程度作為次要訊號，避免它們主導核心日常輸入路徑。

## 分層策略
- `manifests/curated_daily_phrases.tsv` 只收錄應在日常輸入中獲得優先加權的日常/聊天表達。
- `manifests/curated_daily_supplement_phrases.tsv` 用於低頻日常補充：確保完整輸入可列入候選，但不沿用日常/聊天短語的較高權重。
- 該檔案的第五欄可於排序與路徑統計結束後生效：`exact_zero` 產生真正的零權重精確詞條，`exact_rank` 把清單中的非負分值作為固定的精確候選權重，`no_contains` 讓該詞不列入執行階段的子字串熱門度索引，`exact_rank_no_contains` 兼具後兩者，`exact_rank_exact_only` 還讓該詞條不提供補全（只有打完整個讀音才會出現）。
- `manifests/vertical_layers.public.json` 宣告隔離式垂直領域術語層。
- `manifests/vertical/*.tsv` 存放專案維護的垂直領域詞表，例如小說實體、一般專名、人名、地名、國家地區、世界城市、地標、成語典故、電腦術語、政務民生術語、建築術語/建築實體、遊戲術語和遊戲開發術語。
- 垂直領域層可以補充領域詞彙，但不會沿用日常/聊天短語的優先加權。
- fiction 層將小說人物、作品名和世界觀實體與日常/聊天表達及一般專名隔離。
- 啟用中的 proper-noun 層將非人名頭銜、組織、品牌、平台、產品和一般現實專名與日常/聊天表達隔離。
- people-name 層將知名人物與歷史人物姓名和日常/聊天表達、小說實體、非人名專名隔離；Wikidata 補充的人名會刻意使用保守權重，讓完整姓名輸入可列入候選但不排擠常用詞。
- place-name 層以保守權重保留常見國內外地名、國家地區、世界主要城市、景點和地標，讓完整地名輸入可列入候選，但不排擠日常詞候選。
- Wikidata 補充的地名詞條權重會刻意低於專案維護詞條；冷門行政區和地標應該能在完整輸入時出現，但不應壓過常用詞。
- idioms-allusions 層目前結合過濾後的 `THUOCL_chengyu` 子集與專案維護成語典故，以保守權重確保完整成語輸入可列入候選，但不沿用日常/聊天短語的優先加權。
- computing 層目前結合過濾後的 `THUOCL_IT` 子集與專案維護電腦術語。
- civic 層目前收錄稅務、房產、戶籍及其他公共服務術語。
- architecture-terms 層目前結合了專案維護建築術語、Getty AAT 建築術語，以及 Wikidata 建築構件/風格補充。
- architecture-entities 層目前結合了專案維護建築實體，以及保守匯入的 Wikidata 建築地標補充。
- gaming 層目前結合了專案維護遊戲術語、Wikidata 遊戲實體和過濾後的 zhwiki/zhwiktionary 遊戲詞彙標題。
- game-development 層目前結合了專案維護遊戲開發術語、過濾後的 Godot 文件標題、Wikidata 遊戲引擎補充，以及過濾後的 zhwiki/zhwiktionary 遊戲開發詞彙標題。
- medicine 層目前結合了專案維護醫學術語、MeSH 描述符目錄、MeSH 關聯 Wikidata 醫學實體，以及過濾後的 `THUOCL_medical` 子集，並始終與日常/聊天優先路徑隔離。

## 建置與驗證

```powershell
# 完整重建（external_broad + unihan_single + regression checks）
.\rebuild_all.ps1

# 選用：產生待人工審查的人名候選；不會自動匯入正式詞庫
.\scripts\build_people_names_candidates.ps1

# 直接建置單一 profile
.\scripts\build_external_seed.ps1 -Profile external_broad
```

僅修改詞組詞庫時，完整重建會維持現有 Unihan 單字權重穩定。只有明確需要重新校準單字排序層時，才使用 `-RefreshUnihanSingleCharWeights`。

每個讀音下的單字依現代文本的使用頻率排序（`scripts/build_single_char_frequency.py`，2026-10-27）。原來的順序來自 Unihan 的頻率、上世紀八十年代的《現代漢語頻率詞典》計數和學段等級，一些讀音下的生僻字排在常用字之前。這一步把一個讀音原有的權重重新分給它的字，用得最多的字拿最大的權重：計數來自字級語言模型的通用語料，既算總出現次數，也算詞典詞以外單獨出現的次數（`manifests/general_char_counts.tsv`，由 `scripts/count_general_char_frequency.py` 產生），另加聊天訊息裡單獨打出的字，這部分計數不公開。一個字只在它的主讀音下移動，經過審核的相對順序和回歸樣例保持不變。完整重建會保留這些權重；使用 `-RefreshUnihanSingleCharWeights` 之後，需要重新執行這一步，再執行 `scripts/normalize_traditional_forms.py`。

`external_broad` 和 `external_cedict` 在存在
`manifests/vertical_layers.public.json` 時會自動載入該檔案。
