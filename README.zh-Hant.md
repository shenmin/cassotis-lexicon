本儲存庫用於建置與發布 Cassotis IME（言泉輸入法）的簡體、繁體基礎詞庫，以及候選排序所需的統計表。言泉輸入法安裝檔已內建詞庫與統計表，一般使用者直接安裝輸入法即可，無須另外下載。

## 儲存庫職責
- 基於開放詞源與專案維護的補充詞表，建置簡體與繁體基礎詞庫（包含建置指令碼、來源清單及生成產物）。
- 隨版本同步發布供 Cassotis IME 匯入的排序與補全統計表，包括路徑先驗、詞間轉移、字元 n-gram、補全索引、通用文本詞頻、日常對話詞頻及短詞首選表。
- 支援從公開外部詞源可重現地重建完整詞庫（`external_broad`）。
- 維護與生成產物一致的來源標示及授權條款檔案。

## 供 Cassotis IME 排序的資料

除基礎詞表外，本儲存庫也發布供 Cassotis IME 匯入本機 SQLite 詞庫資料庫的統計表。這些統計表僅用於排序與補全，並非可直接輸入的詞條，因此不計入上方的詞庫快照。表中僅記錄頻次、詞對關係與字元 n-gram，不包含語料原句，且統計來源已排除輸入法的基準測試集。輸入法自身的字元級語言模型、決策策略與結構排序器由 IME 主儲存庫負責訓練與發布，詳見 [模型與排序](https://github.com/shenmin/cassotis-ime/blob/master/README.zh-Hant.md#模型與排序)。

下表中的版本區間表示對應版本的發布產物維持一致；各項記錄數均不含檔案標頭。

查詢路徑先驗與詞級二元、三元轉移關係由本儲存庫建置流程產生，供 Cassotis IME 對長句切分路徑評分，同時也用於短詞與詞外短語的詞間轉移評估。具平滑退避機制的正向、反向字元級 n-gram 模型由 IME 訓練工具產生，再交由本儲存庫統一做版本管理與發布；輸入法匯入後將其作為主語言模型之外的統計特徵使用（如用於補全排序與產生短詞首選表）。

主要版本演進：

- **v1.12.0**：進一步擴充高頻詞間轉移，並新增有語料依據的相鄰單字（1+1）轉移關係（排除已收錄的二字詞，且要求使用常用讀音並獲多個獨立來源佐證）。
- **v1.13.0**：新增反向字元 n-gram 模型，用於雙向路徑評分。
- **v1.14.0**：更新查詢路徑先驗，支援輸入法的精確詞錨定與短語續接路徑。
- **v2.3.0**：繁體統計表全面改用臺灣用字，字形統一後重複的記錄合併保留一筆。

短詞首選表（`data/generated/dict_short_promotion_{sc,tc}.txt`）針對二至四音節查詢，預先記錄僅憑詞庫排序時應當排到預設首詞之前的精確比對詞條。此表由 Cassotis IME 的專用離線工具依建置完成的詞庫產生（見 IME 儲存庫的 `out/rebuild_short_promotion.ps1`），用以取代早期的執行階段短詞殘差模型（該模型現僅保留於此離線產生工具中）。每筆記錄均附帶決策時的候選詞列表與權重，僅在詞條與權重未變時生效；舊版詞庫遺留的不符記錄會自動略過，不會引發錯誤。

通用詞頻表（`data/generated/dict_word_frequency_{sc,tc}.txt`）記錄二字及以上詞條在通用中文語料中獨立成詞的出現頻次，按 `100 * log10(1 + 次數)` 折算分值；繁體詞條沿用對應簡體形式的頻次。原始計數（`manifests/general_word_counts.tsv`，由 `scripts/count_general_word_frequency.py` 產生）統計自 Cassotis IME 字元級語言模型的通用語料，採用最少詞數切分，因此包含在長詞內部的短詞不重複計入。後續新增詞條僅統計其獨立成詞頻次，不影響既有詞條計數。無前後文時，Cassotis IME 會參考此表在同音詞之間取捨。

會話詞頻表（`data/generated/dict_conversation_frequency_{sc,tc}.txt`）採用相同的切分與折算方式，統計日常對話語料 LCCC-large（Wang 等，“A Large-Scale Chinese Short-Text Conversation Dataset”，NLPCC 2020；MIT 授權條款）中的詞頻（原始計數見 `manifests/conversation_word_counts.tsv`，僅保留頻次）。無前後文時，若詞庫預設首詞在日常對話中遠比競爭詞常見，而通用語料僅微弱偏向後者，Cassotis IME 會依據此表保留預設首詞。由於 LCCC 語料經過敏感詞過濾，未出現在表中的詞僅視為缺少對話統計，不作為降權依據。

輸入法建置執行階段詞庫時會強制驗證這三張表，缺少任何一張都會直接報錯中止，避免在未察覺的情況下導致短詞排序品質下降。

v1.16.0 引入了基於語料統計的補全熱門度先驗與預先建立的 Top-K 前綴查詢索引，讓輸入法無須在執行階段列舉組合，即可區分常用補全與冷門專業詞彙。熱門度先驗作為獨立快照建置，記錄數不必與目前主詞庫詞條數一致，也不等同於實際可提示的補全數量；低頻專業詞能否參與短前綴補全或 Tab 預測，仍受獨立規則限制。

建置流程也會從高頻可靠的精確詞路徑中離線提取獨立的轉移補全索引，為每個輸入前綴最多保留 6 個經過複核的候選方案。實際排序時優先顯示使用者歷史補全；基礎詞庫補全與轉移補全則綜合熱門度、前文語境及語料頻次擇優比較。

## 匯入後的最佳化與篩選（外部來源）
- 對不同格式詞源匯入的詞條做規範化與去重處理。
- 綜合基礎詞頻、文件頻率（DF）及頁面瀏覽熱度計算權重，並做均衡縮放。
- 從已有充分依據的較長口語短語中提取常用短前綴，讓常見句型轉折與銜接表達更容易優先出現。
- 降低缺乏多源佐證的專有名詞、疑似人名及長尾雜訊權重，減少冷門專名排擠常用詞。
- 執行面向輸入法情境的有效性篩選（如字形可顯示性與字元集範圍檢查），確保產生的詞條適用於主流 Windows 應用程式環境。
- 結合規則修正與迴歸測試樣本驗證，維持跨版本排序行為穩定。

## 覆蓋重點
- 優先改善日常表達與對話式輸入體驗，而非單純追逐網路熱門詞。
- 運用開放詞源補齊常用短表達、句型轉折、語氣詞與口語連接詞。
- 對開放詞源遺漏的高價值日常表達，透過精簡的專案維護白名單定向補充。
- 將專有名詞與網頁熱度控制在次要權重，避免干擾核心日常輸入路徑。

## 分層策略
- `manifests/curated_daily_phrases.tsv`：專門收錄享有日常輸入優先加權的常用口語與聊天短語。
- `manifests/curated_daily_supplement_phrases.tsv`：收錄低頻日常補充詞條，確保完整拼音輸入時可列入候選，但不享有日常聊天短語的高優先權重。
- 上述補充詞表可選配第五欄模式（於一般排序與路徑統計完成後生效）：`exact_zero` 產生零權重的精確比對詞條；`exact_rank` 將清單中的非負分值直接作為固定的精確候選權重；`no_contains` 使詞條不寫入執行階段的子字串熱門度索引；`exact_rank_no_contains` 同時啟用 `exact_rank` 與 `no_contains`；`exact_rank_exact_only` 在此基礎上進一步停用前綴補全（僅在輸完完整拼音時出現）。
- `manifests/vertical_layers.public.json` 宣告各獨立領域詞層的設定與詞源，`manifests/vertical/*.tsv` 存放專案維護的各領域詞表。所有領域詞層均獨立於日常聊天短語的優先加權路徑之外，避免專業詞彙與專名干擾日常輸入：
  - 小說實體層（`fiction_entities`）：收錄小說人物、作品名與設定詞彙，與日常短語及一般專名隔離。
  - 一般專名層（`proper_nouns`）：收錄頭銜、機構、品牌、平台、產品等非人名現實專有名詞。
  - 人名層（`people_names`）：收錄公眾人物與歷史人物姓名（與小說人物及非人名專名隔離）；其中 Wikidata 補充人名採用保守權重，確保輸入完整姓名時可選，同時不排擠常用詞。
  - 地名層（`place_names`）：以保守權重收錄國內外地名、國家地區、世界主要城市、景點與地標；Wikidata 補充地名的權重低於專案維護詞條，讓冷門行政區與地標在完整輸入時可選，但不會壓過常用詞。
  - 成語典故層（`idioms_allusions`）：包含過濾後的 `THUOCL_chengyu` 子集與專案維護的成語典故，採用保守權重，支援完整成語輸入且不排擠日常短語。
  - 電腦層（`computing`）：包含過濾後的 `THUOCL_IT` 子集與專案維護的電腦術語。
  - 政務民生層（`civic`）：收錄稅務、房產、戶籍及其他公共服務相關術語。
  - 建築術語層（`architecture_terms`）與建築實體層（`architecture_entities`）：前者整合專案維護術語、Getty AAT 建築術語及 Wikidata 建築構件/風格詞條；後者包含專案維護建築實體及保守權重匯入的 Wikidata 建築地標。
  - 遊戲層（`gaming`）：整合專案維護遊戲用語、Wikidata 遊戲實體，以及過濾後的中文維基百科與維基詞典（`zhwiki`/`zhwiktionary`）遊戲詞條。
  - 遊戲開發層（`game_dev`）：整合專案維護開發術語、過濾後的 Godot 中文文件標題、Wikidata 遊戲引擎名稱，以及過濾後的 `zhwiki`/`zhwiktionary` 相關詞條。
  - 醫學層（`medicine`）：整合專案維護醫學術語、MeSH 主題詞目錄、關聯 MeSH 的 Wikidata 醫學實體，以及過濾後的 `THUOCL_medical` 子集。

## 建置與驗證

```powershell
# 完整重建（external_broad + unihan_single + regression checks）
.\rebuild_all.ps1

# 選用：產生待人工審查的人名候選；不會自動匯入正式詞庫
.\scripts\build_people_names_candidates.ps1

# 直接建置單一 profile
.\scripts\build_external_seed.ps1 -Profile external_broad
```

僅修改多字詞表時，完整重建會維持現有的 Unihan 單字權重不變；僅在需要重新校準單字排序時，才需使用 `-RefreshUnihanSingleCharWeights`。

同一讀音下的單字依現代文本中的實際使用頻率排序（`scripts/build_single_char_frequency.py`，2026-10-27）。早期單字順序依賴 Unihan 頻次、上世紀八十年代《現代漢語頻率詞典》及學段字表分級，導致部分讀音下生僻字排到了常用字前面。現行指令碼將該讀音原有的權重集合依現代字頻重新分配給同音單字，使用最頻繁的字獲得最高權重。字頻統計綜合了字元級語言模型通用語料中的總頻次與獨立單字（多字詞之外）頻次（`manifests/general_char_counts.tsv`，由 `scripts/count_general_char_frequency.py` 產生），以及聊天訊息中單字獨立輸入的頻次（私有統計，不公開）。每個字僅在其主讀音下調整位次，同時嚴格保留人工審核的先後順序與迴歸測試樣本。

在繁體詞庫中，對於「一簡對多繁」的同源單字，由於通用字頻基於簡體統計，且語言模型處理繁體時同樣先對應為簡體字，兩者均無法區分這些繁體字形的常用度。因此，這類單字在其主讀音下依繁體文本的實際用字比例排序：先將通用語料逐句經 OpenCC 轉為繁體並統計各字形佔比（`manifests/traditional_char_shares.tsv`，由 `scripts/count_traditional_char_shares.py` 產生），再由 `scripts/order_traditional_shared_chars.py` 完成排序。臺灣文本中未使用的異體字排在已出現字形之後；個別多音字因各讀音權重接近，由人工指定參與重排的主讀音。日常完整重建會保留上述單字權重；若使用了 `-RefreshUnihanSingleCharWeights`，需依序重新執行這兩個單字排序指令碼，最後再執行 `scripts/normalize_traditional_forms.py`。

當存在 `manifests/vertical_layers.public.json` 時，`external_broad` 與 `external_cedict` 建置流程會自動載入該設定檔。
