## 儲存庫職責
- 維護詞庫建置指令碼、清單檔案與生成產物。
- 發布供 Cassotis IME 使用的版本化詞庫與本機語言模型產物。
- 支援以外部來源建立詞庫，以及可重現的詞庫生成流程。
- 確保來源標示檔案與生成產物保持一致。

從 Cassotis IME v1.3.0 開始，這些詞庫約束和統計訊號也會支援專案首個可部署的長句神經殘差重排器。精簡的神經模型由 IME 專案訓練、匯出和部署，因此不計入可輸入詞條數量，也不列入上表的模型資料規模。v1.3.0 的詞路徑轉移關係與字元 n-gram 數量和 v1.2.0 相同，屬於正常結果。

Cassotis IME v1.4.0 新增獨立的短詞前後文重排器，並重複利用本儲存庫發布的字元 n-gram 訊號。這個精簡模型同樣由 IME 專案訓練、匯出和部署，因此不會在上表中增加新的模型資料類別。

Cassotis IME v1.5.0 又為短詞前後文排序加入獨立訓練的殘差複核階段。該殘差模型同樣由 IME 專案維護，因此 v1.5.0 的詞路徑轉移關係與字元 n-gram 數量維持不變，屬於正常結果。

Cassotis IME v1.6.0 將長句解碼擴充為分別訓練的搜尋狀態、第二階段和最終候選排序模型，並加入學習而得的後備策略。這些精簡模型均由 IME 專案訓練和部署，因此不會在本表中增加新的資料類別。v1.6.0 這一列反映 Lexicon 發布的查詢路徑先驗更新；詞路徑轉移關係與字元 n-gram 產物則和 v1.5.0 相同。

Cassotis IME v1.7.0 使用詞庫發布的詞路徑轉移證據，在四音節輸入中保留可靠的雙詞組合，同時排除缺乏依據的組合。v1.7.0 這一列反映目前詞庫重新產生的查詢路徑先驗；詞路徑轉移關係與字元 n-gram 產物和 v1.6.0 保持一致。

Cassotis IME v1.9.0 使用這些詞庫約束和統計模型產物，建立結構多樣的長句完整候選池，再交由統一的語料訓練模型排序。精簡的完整候選池與殘差排序模型仍由 IME 專案維護；因此 v1.9.0 這一列反映查詢路徑先驗的更新，詞路徑轉移關係與字元 n-gram 數量則保持不變。

v1.10.0 新增由語料證據支援、約束嚴格的 1+2 和 2+1 精確詞轉移，用於改善三音節短詞續接，同時避免引入缺乏依據的組合。

v1.11.0 保留全部既有轉移權重，並從清理後的小說、聊天和大規模中文語料中獨立計數，擴充 1+2、2+1、2+2、2+3 和 3+2 精確詞轉移；新增項還必須通過來源依據、競爭路徑與已觀察到的同音詞驗證。

統計模型只儲存短距離詞語轉移和字元 n-gram，不會儲存完整訓練句子。獨立的長句與短詞基準案例均不參與訓練。執行階段由 IME 在本機計算統計訊號並執行精簡的原生重排器，不會啟動 PyTorch/ONNX 執行環境或外部模型服務，也不需要網路連線或 GPU。長句評估方法請參閱 [IME 基準測試說明](https://github.com/shenmin/cassotis-ime/blob/master/BENCHMARK.CN.md)。

## 匯入後的最佳化與篩選（外部來源）
- 統一不同來源的詞條格式，並移除重複項目。
- 綜合多個訊號（基礎頻率、DF/頻率側訊號、頁面熱度）計算權重，並做平衡縮放。
- 從已有充分依據的較長口語表達中衍生較短的日常/聊天前綴，讓常見句型轉折更容易優先出現。
- 降低訊號薄弱的專名、疑似人名和長尾雜訊權重，減少冷門專名排擠常用詞。
- 套用針對 IME 的有效性篩選（例如可顯示性與字元書寫系統限制），確保輸出適用於主流 Windows 用戶端。
- 透過規則修正與迴歸案例驗證維持排序行為穩定。

## 覆蓋重點
- 優先改善日常表達和對話式輸入，而不只追逐熱門詞。
- 藉助開放詞彙來源補回常見短表達、句型轉折、語氣詞和口語連接詞。
- 對開放來源仍然缺失但價值很高的日常表達，保留少量專案維護白名單。
- 將專名和網頁熱門程度作為次要訊號，避免它們主導核心日常輸入路徑。

## 分層策略
- `manifests/curated_daily_phrases.tsv` 只收錄應在日常輸入中獲得優先加權的日常/聊天表達。
- `manifests/curated_daily_supplement_phrases.tsv` 用於低頻日常補充：確保完整輸入可列入候選，但不沿用日常/聊天短語的較高權重。
- `manifests/vertical_layers.public.json` 宣告隔離式垂直領域術語層。
- `manifests/vertical/*.tsv` 存放專案維護的垂直領域詞表，例如小說實體、一般專名、人名、地名、國家地區、世界城市、地標、成語典故、電腦術語、政務民生術語、建築術語/建築實體、遊戲術語和遊戲開發術語。
- 垂直領域層可以補充領域詞彙，但不會沿用日常/聊天短語的優先加權。
- fiction 層將小說人物、作品名和世界觀實體與日常/聊天表達及一般專名隔離。
- 啟用中的 proper-noun 層將非人名頭銜、組織、品牌、平台、產品和一般現實專名與日常/聊天表達隔離。
- people-name 層將知名人物與歷史人物姓名和日常/聊天表達、小說實體、非人名專名隔離；Wikidata 補充的人名會刻意使用保守權重，讓完整姓名輸入可列入候選但不排擠常用詞。
- place-name 層以保守權重保留常見國內外地名、國家地區、世界主要城市、景點和地標，讓完整地名輸入可列入候選，但不排擠日常詞候選。
- Wikidata 補充的地名詞條權重會刻意低於專案維護詞條；冷門行政區和地標應該能在完整輸入時出現，但不應壓過常用詞。
- idioms-allusions 層目前結合過濾後的 `THUOCL_chengyu` 子集與專案維護成語典故，以保守權重確保完整成語輸入可列入候選，但不沿用日常/聊天短語的優先加權。
- computing 層目前結合過濾後的 `THUOCL_IT` 子集與專案維護電腦術語。
- civic 層目前收錄稅務、房產、戶籍及其他公共服務術語。
- architecture-terms 層目前結合了專案維護建築術語、Getty AAT 建築術語，以及 Wikidata 建築構件/風格補充。
- architecture-entities 層目前結合了專案維護建築實體，以及保守匯入的 Wikidata 建築地標補充。
- gaming 層目前結合了專案維護遊戲術語、Wikidata 遊戲實體和過濾後的 zhwiki/zhwiktionary 遊戲詞彙標題。
- game-development 層目前結合了專案維護遊戲開發術語、過濾後的 Godot 文件標題、Wikidata 遊戲引擎補充，以及過濾後的 zhwiki/zhwiktionary 遊戲開發詞彙標題。
- medicine 層目前結合了專案維護醫學術語、MeSH 描述符目錄、MeSH 關聯 Wikidata 醫學實體，以及過濾後的 `THUOCL_medical` 子集，並始終與日常/聊天優先路徑隔離。

## 目錄結構
- `data/generated/`：產生的詞庫檔案和版本化語言模型產物。
- `manifests/`：來源/授權條款清單與迴歸樣本。
- `manifests/pinyin_overrides.tsv`：專案維護的詞條級讀音覆蓋表。
- `manifests/vertical/`：專案維護的隔離式垂直領域詞表。
- `scripts/`：建置、驗證和匯出輔助指令碼。
- `reports/`：建置報告。
- `rules/`：匯出與發布規則。
